# Тест совместимости: честная метрика на слепой выборке — пилот ролей пройден, ждём решения о доработке и полном прогоне

Проект: `~/projects/compatibility-test` (ветка `main`; каждый push в main → тесты в CI → GitHub Pages
https://vsvasilenko111.github.io/compatibility-test/). Пользователь пишет по-русски, отвечать по-русски, кратко
и без жаргона; иногда пишет в английской раскладке («crjkmrj tot ;lfnm» = «сколько ещё ждать»).

## 1. Цель
Сделать метрику качества теста честной: слепая синтетическая выборка из реальных долей (аудитория — пары
**20–30 лет**, Россия), исход пары — по заранее записанной модели из литературы, а не по замыслу автора или мнению
LLM; каждый шаг конвейера критикуют другие агенты; персонажи — реалистичные, не «позитивные».

## 2. Что сделано (всё закоммичено)
**Тест (прод):**
- Банк **v15**: 153 вопроса, 5 вариантов словами, совпадение — таблица 5×5 `MATCH` (`src/scoring/primitives.ts`),
  все вопросы равны, 5 важных сфер ×3 (и «отношения», и «друг»), 18 сфер (`src/questions/spheres.ts`),
  формат ссылки 5. `COMPATIBLE_SINCE = 15` (старые ссылки → «Тест обновился»).
- Защита выпущенных версий: `src/questions/released.json` + `tests/released.test.ts` + `scripts/release-bank.ts`;
  правило «как менять вопросы» — в README. `docs/questions.md` собирается `python3 scripts/questions-doc.py`.
- 228 тестов зелёные.

**Метрика старой синтетики** (`research/metric/`, агент `metric-owner`): v15 на рабочей части 77,2 [67,7; 84,7];
v13→v15 +3,5 [−1,2; 8,5] — шум. Старая синтетика замкнута (биографии писались парами под исход). Разбиение
`split.json` заморожено; проверочная часть — только `audit.ts --holdout` с записью в журнал.

**Источники** (`research/sources/`): datasets.md, base-rates.md, methods.md — с разделами «Проверка источников».

**Агенты** (`.claude/agents/`): metric-owner, pipeline-critic (аудитория 20–30), оценщики judge-gottman (opus),
judge-lawyer (sonnet), judge-svakha (sonnet), judge-actuary (opus), judge-friend (haiku, 26 лет), chronicler (sonnet),
общие правила `_judge-common.md`. Внешних API-ключей нет и не будет — только Claude.

**Слепая выборка** (`research/blind/`, design.md ред. 4 + раздел 16; предрегистрация — коммит 925721a):
- 100 человек (Москва 40, Казань 30, Ярославль 30), «правда» + самоотчёт с приукрашиванием, 180 пар (50 + 130),
  исходы и модель — `private/`, проверочная часть — `sealed/` (лимит 3 запуска через `seal.py --open`).
- Главная метрика — Spearman балла теста с риском распада по скелету; ансамбли 30 + 16 формул другого устройства,
  правка принимается при выигрыше во всех вариантах устройства. Потолок самоотчёта ~0,66 AUC.
- **Я (оркестратор) видел центральную формулу исхода** в раннем отчёте — ограничение; отчёты агентов больше не
  показывают коэффициенты. Не подгонять вопросы под формулу.
- Отчёты агентов по всем этапам — `research/blind/reviews/01…03`.

**Исполнитель ролей** `research/blind/run_roles.py`: каждая роль — отдельный процесс
`claude -p … --model <полное имя> --effort … --tools "" --strict-mcp-config --mcp-config '{"mcpServers":{}}'
--setting-sources project --no-session-persistence --system-prompt … --output-format stream-json --verbose`
из `mktemp -d` вне проекта (`--bare` не работает — нет API-ключа; без `--setting-sources project` висит на хуках).
Роли: A досье (claude-opus-5-5), B самоописание (claude-sonnet-5-5), C восстановитель (claude-opus-5),
D ответы на тест (claude-opus-5-5, пачками по 9–10, без прошлых ответов, случайный порядок, половина вариантов
перевёрнута). Кеш по хешу; `check_transcripts.py` проверяет init (пустые tools/mcp, та модель, cwd вне проекта).

**Пилот на 5** (жребий из рабочей части): изоляция подтверждена критиком, 105 вызовов без ошибок, ~3 мин,
~4% пятичасового окна подписки. **Вердикт критика: полный прогон пока не запускать.**

## 3. Следующие шаги (ждём ответа пользователя на два вопроса)
Пользователю предложено (последнее сообщение): (1) исправления, (2) повторный пилот на 10, (3) полный прогон
порциями. Вопросы к нему: запускаем ли и приемлемо ли расходование лимитов подписки (полный прогон ≈ +80%
пятичасового окна и ≈ +20% недельного — только порциями по 15–20 человек, ждать `resetsAt` при лимите).

Исправления по критике пилота (`reviews/03-pilot.md`, раздел critique):
1. Пилот подобрать стратифицированно: измены, долг, избегающая привязанность, уход от разговора, традиционные роли,
   Ярославль, только школа — чтобы проверки C/D не были холостыми; TASK_C — «нет данных» отдельно от «нет».
2. Добавить в запись («правда» и самоотчёт) черты непокрытых сфер — досуг, юмор, близость, родня, питание, спорт —
   с долями из base-rates.md (жребий после существующих, исходы не менять), иначе D отвечает «по умолчанию» и
   выбирает важные сферы по устройству записи; или записать в design.md, что эти сферы синтетика не судит.
3. B: манера речи по жребию (оправдывается / преуменьшает / винит других / не задумывается), можно пропускать
   некритичные поля, запрет анкетных слов (организованность, доброжелательность, «как чувство», «посередине»,
   «уровень») — автоматический брак до C; запрет раскаяния, которого нет в записи.
4. D: убрать «не лучшая версия себя» из SYS_D (давало резкость в ссорах у всех); выводить сдвиг по вопросам/сферам.
5. Браковать U+FFFD в ответах A/B; A — без новых фактов о деньгах, вере, работе; хранить текст задания рядом с raw.
6. Затем: повторный пилот на 10 → полный прогон 100 порциями → оценщики (5 judge + chronicler по досье с
   непрозрачными id) → metric-owner считает Spearman + ансамбли (без показа мне коэффициентов) → критик.
Честное ожидание: балл ниже прежних 78 (по Joel 2020 будущее предсказывается слабо).

## 4. Ограничения
- В прод только push в main; правка банка — только новой версией (`scripts/release-bank.ts`).
- Не трогать `research/metric/split.json`, `research/blind/sealed/`; проверочные части — только через их скрипты.
- Агентам — отдельные подпапки scratchpad (параллельные агенты конфликтуют).
- Коммиты с подписью `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`.
- Пользователь не любит отбор вопросов «по ощущению» — опираться на данные; правила банка — README и
  `docs/questions.md` (принципы 1–9). Workflow-агенты иногда путают задание с «запросом статуса» — писать явно
  «это не запрос статуса, выполняй».
