## pilot

## Пилот ролей A–D на 5 человек: порог «можно масштабировать» выполнен, есть замечания

**Время и цена.** 166 с по часам при 4 процессах (суммарно около 658 с на вызовы). 105 вызовов: A — 5, B — 5, C — 10, D — 85. Счётчик claude показывает $3,25 по прейскуранту (`costBasis: list`). Ошибок API, выдуманных инструментов и неразборчивых ответов — 0. Повторный запуск с `--no-call` взял все 105 ответов из кеша и ни разу не вызвал модель.

### Как устроен исполнитель (`research/blind/run_roles.py`)

- **Вызов роли.** Каждый вызов — отдельный процесс `claude -p` из свежего `mktemp -d` вне проекта. Флаги: `--model` с полным именем и `--effort` из `models.json`, `--tools ""`, `--strict-mcp-config --mcp-config '{"mcpServers":{}}'`, `--setting-sources project`, `--no-session-persistence`, свой `--system-prompt` для каждой роли, `--output-format stream-json --verbose`. Из окружения убраны переменные родительской сессии `CLAUDE_CODE_*`, `CLAUDECODE` и `CLAUDE_EFFORT`.
- **`--bare` не работает.** С ним вызов падает с «Not logged in»: флаг принимает только `ANTHROPIC_API_KEY`, вход по OAuth не читает, а ключа в окружении нет. Его заменяют флаги выше. Пробный вызов: системная часть около 600 токенов, CLAUDE.md пользователя туда не попал.
- **Модели.** Все четыре полных имени из `models.json` существуют (`claude-opus-5-5`, `claude-sonnet-5-5`, `claude-opus-5`, `claude-haiku-5-5`). Замен не понадобилось, B≠A, B≠D, C≠B выполняются.
- **Роли.**
  - A пишет досье по `inputs/truth`, B — самоописание по `inputs/self` отдельным вызовом.
  - C восстанавливает 12 полей по одному тексту. Если текст забракован, автор переписывает его, до 3 попыток, потом пометка «текст неверен».
  - D отвечает пачками по 9–10 вопросов (16 пачек) и не видит своих прошлых ответов. Порядок вопросов случаен, у половины вопросов варианты показаны в обратном порядке; зерно `answerer_order` плюс хеш id. Ответы переводятся обратно в номера банка 1..5. Отметки «не обсуждается» — только у `firm`, пропуск — только у `optional`. 5 важных сфер выбираются 17-м вызовом.
- **В заданиях ролям** есть всё из п. 3 задачи: люди обычные, не лучшая версия себя; противоречия не сглаживать; D отвечает от первого лица, как человек сам о себе думает.
- **Выдуманные инструменты.** Ответ со следами «чтения файла» или вызова инструмента бракуется, переносится в `raw_rejected/` и перезапрашивается.
- **Кеш и защита.** Кеш — по хешу роли, модели, effort, промптов и номера попытки. Одновременно не больше 4 процессов. `guard()` запрещает чтение и запись в `private/`, `sealed/`, `people.json` и `selfreport.json`. Шаблоны промптов с хешами лежат в `prompts/roles.json`.

После пилота добавлена запись 16.9 с итогом.

**Проверка транскриптов.** В `check_transcripts.py` добавлена проверка потока. Первой строкой каждого сырого файла идёт заявка исполнителя (`runner_request`). Дальше проверяется:

Проверка ловит все 6 испорченных копий (инструменты, MCP, модель, нет заявки, `cwd` в проекте, `num_turns`) и пропускает исправную.

Зерно — `SeedSequence(20261028).spawn(19)[18]`, выбор только из рабочей части (58 человек). Пять слоёв по «правде»: тревожный q7kd, конфликтный ern9, пьющий jmsb, благополучный ftwc, религиозный nihq.

### Проблемы

1. **D сжимает разброс.** На `regul-04` у всех пятерых ответ 1 («остаюсь в разговоре»). Крайние варианты — 5–10% ответов, средний — 30–40%. Проверку 3.3 (отношение SD не ниже 0,8, ранговая корреляция не ниже 0,5) на 100 людях нужно сделать обязательно; на пятерых она не считалась.
2. **Самоописания B похожи на пересказ записи.** Местами анкетные слова («организованность», «как чувство», «посередине»), поля идут почти по порядку записи. Из-за этого проверка C может проходить слишком легко.
3. **Разбор ответа C.** Модель пишет значения неточно («вне конфессии» вместо «другое / вне конфессии»). Добавлена нормализация; это нашлось на пробном прогоне до пилота, пробные выходы удалены.
4. **Effort не проверить.** В событии `init` его нет; сверяется только заявка исполнителя.
5. **Прежние ограничения партии.** Все роли из одного семейства, A и D — одна модель. На пятерых сдвиг измерен грубо.

Ничего не коммитил.

## critique

## Критик: пилот ролей A–D (5 человек). Вердикт: полный прогон на 100 человек пока не запускать

Изоляция работает: я проверил её сам, и она подтвердилась. Но порог 16.7 пройден на пятерых людях, у которых нет как раз тех свойств, где ломаются B, C и D. Ещё две находки меняют метрику: D выбирает важные сферы по устройству записи, и все самоописания написаны одним голосом. Файлы не правил.

### Замечания по убыванию влияния на метрику

**1. Пилот однороден там, где проверка должна была сработать. Критичные ветки порога проверены вхолостую.**
- **Что не так.** Сравнил пятерых (`pilot/pilot.json`) с распределением по `inputs/truth/` для 100 человек:
  - измены в прошлом: в пилоте 0 из 5, во всей выборке 19%; признаёт измену в самоотчёте 0 из 5, в выборке 6%;
  - проблемный долг: 0 из 5, в выборке 6%;
  - избегающий или тревожно-избегающий тип: 0 из 5, в выборке 27%;
  - уход от разговора «иногда» или «часто»: 0 из 5, в выборке 53%;
  - «глава семьи — мужчина»: 0 из 5, в выборке 19%; быт «в основном женщина» или «в основном мужчина»: 0 из 5, в выборке 23%;
  - Ярославль: 0 из 5, в выборке 30%; только школа: 0 из 5, в выборке 7%;
  - Москва — 4 из 5.
- **Почему проверка C пустая.** В задании C (`run_roles.py`, TASK_C) сказано: для да/нет ставить «нет», если в тексте нет указаний. Если эталон «нет», текст, который о поле молчит, проходит сам собой. Так у 9 из 10 текстов проверены «измены» и «долг» из числа критичных полей. «Рискованное питьё» в самоописании по правилу 16.5 всегда «нет». На деле ветку «да» проверило одно досье: jmsb, рискованное питьё.
- **Пример конструктора неудачен.** `regul-04` = 1 у всех пятерых — не признак сжатия: у всех пятерых и в «правде», и в самоотчёте уход от разговора «редко» или «почти никогда».
- **Почему это меняет метрику.** Порог «можно масштабировать» не говорит, как B смягчает признанную измену или долг, ловит ли C пропуск таких фактов и как D отвечает за избегающего или молчащего в ссорах. На этих людях тест и различает пары.
- **Правка.**
  - Добрать 4–5 человек из рабочей части отдельным зерном с новым именем, по слоям: изменял и признаёт; изменял и не признаёт; проблемный долг; избегающий или тревожно-избегающий; уход «часто»; традиционные роли; хотя бы один из Ярославля или только со школой. Цена около $3.
  - В порог добавить: хотя бы один текст с критичным «да» восстановлен верно.

**2. D отвечает «по умолчанию» на вопросы, о которых в самоописании ничего нет. Важные сферы выбирает по устройству записи.**
- **Что не так** (`answers/*.json`):
  - 17 из 153 вопросов — один и тот же ответ у всех пятерых. Например: life-01, contact-01, budget-03, home-02, loyalty-02, intimacy-02, relatives-02, life-05, honesty-03, budget-06, kids-06, money-07, regul-07, conflicts-07.
  - У 69 из 153 вопросов разброс ответов не больше одной ступени.
  - Попарно точных совпадений 54–83 из 153. При таких долях вариантов случайно ожидается около 40–45.
  - Почти все совпадающие вопросы — из сфер, которых нет в записи: юмор, близость, родня, еда, спорт.
- **Важные сферы:**
  - «дети» выбрали 5 из 5, «роли» 4 из 5, «карьера» 4 из 5;
  - «юмор», «общение», «досуг», «честность», «близость», «родственники», «проявления любви» не выбрал никто.
  - Первые три — ровно те сферы, о которых в каждом самоописании есть обязательная фраза: дети, роли, карьера или баланс.
- **Почему это меняет метрику.** Важные сферы весят втрое. Синтетический балл пары перекошен к сферам, которые описаны в записи. По сферам вне записи все пары совпадают одинаково, так что правки этих вопросов в оценке будут выглядеть нейтральными, что бы в них ни меняли. Проверка 3.3 (SD и ранги) это поймает только частично: она смотрит на сопоставленные поля, а не на вопросы вне записи.
- **Правка.**
  - Либо добавить в запись («правда» и самоотчёт) признаки для непокрытых сфер — досуг, юмор, близость, родня, питание, спорт — с долями по `base-rates.md`.
  - Либо заранее записать в `design.md`: синтетика не судит о правках вопросов вне записи и не годится для проверки весов важных сфер.
  - Важные сферы отдельно сверить с реальными данными, если они есть. Нельзя молча принимать выбор D.

**3. Самоописания B написаны одним шаблоном: каждое перечисляет почти все поля записи одним голосом «раскаявшегося».**
- **Что не так** (`texts/self/*.md`):
  - В 5 из 5 есть «кредитов, кредиток и рассрочек», «глава семьи», «поровну», «по мелочам», дача, «вещи или впечатления», баланс или карьера, отчим.
  - Слово «организованность» — в 5 из 5, «доброжелательность» — в 4 из 5, «как чувство» — в 2 из 5. Задание это прямо запрещает.
  - У всех пятерых один ход: признание недостатка, затем раскаяние, затем «но так есть». Примеры: «потом жалею, это моё слабое место, я над ним думаю» (q7kd), «потом не горжусь этим… без двойного дна» (nihq), «зато честная и открытая» (ern9). У ern9 «правда» — привирает часто.
  - Досье тоже копируют названия полей: «в её жизни появился отчим или мачеха» (`texts/dossier/q7kd.md`).
- **Почему это меняет метрику.**
  - Каждый синтетический человек — проницательный и самокритичный. Именно этот перекос синтетики `pipeline-critic.md` велит искать (рефлексирующие люди). Реальный конфликтный человек чаще преуменьшает и винит партнёра.
  - Полный перечень полей делает ответы D почти функцией записи: шум реального самоописания пропал.
  - Почти дословная передача уровней объясняет, почему C всё восстанавливает с первой попытки. Проверка C подтверждает пересказ, а не естественность текста.
- **Правка.**
  - До C поставить автоматический брак по списку анкетных слов: организованность, доброжелательность, «как чувство», «посередине», «средняя», «уровень».
  - В задании B разрешить пропускать некритичные поля и задать манеры речи по жребию: оправдывается, преуменьшает, винит других, не задумывается.
  - Запретить итоговые фразы с самооценкой и раскаяние, которого нет в сведениях.

**4. D перебарщивает с резкостью на вопросах о ссорах. Сдвиг по пяти вопросам это прячет.**
- **Что не так:**
  - `regul-07` = 4 («Отвечу резко») у всех пятерых;
  - `regul-01` = 4–5 у всех; у jmsb 5 («сразу и резко»), хотя в самоописании «меня трудно выбить из колеи»;
  - `conflicts-02` = 4 («Громко») у 4 из 5.
  - Люди с критикой в ссорах «иногда» (q7kd, ern9, nihq) отвечают так же, как люди с «часто» (jmsb, ftwc). D реагирует на сам факт признания, а не на его степень.
  - Причина, скорее всего, в системном промпте D (`SYS_D`): «Это обычный человек, а не лучшая версия себя». Он толкает D против желательности, хотя желательность по замыслу уже заложена в самоотчёт.
- **Почему это меняет метрику.** Средний сдвиг +0,2 по пяти вопросам складывается из разнонаправленных сдвигов по сферам. Ссоры у синтетических людей выглядят хуже, чем они сами о себе думают, и различие между «иногда» и «часто» теряется.
- **Правка.**
  - Убрать «не лучшая версия себя» из `SYS_D`. Оставить «как ты сам о себе думаешь, не сглаживая».
  - В `pilot_check.py` выводить сдвиг по каждому вопросу и сфере, а не только среднее.

**5. Лимиты аккаунта выдержат не весь прогон.**
- **Что не так.** В сырых потоках (`rate_limit_event`) пятичасовое окно выросло с 0,51 до 0,55 за пилот, а это 5 человек. На 100 человек это около +80% окна, сверх уже занятого. Недельное окно выросло с 0,17 до 0,18, то есть около +20% на весь прогон. Превышение запрещено (`org_level_disabled`). Исполнитель (`call`) повторяет вызов 4 раза с паузами 10–40 с, в сумме около 100 с. Лимит этим не переждать: люди упадут с ошибкой, прогон оборвётся.
- **Правка.** Запускать порциями по 15–20 человек через `--ids`, перед порцией смотреть занятость окна. При ответе «лимит» ждать до `resetsAt`, а не 100 с. Кеш позволяет продолжить с места остановки.

**6. Битый символ в самоописании дошёл до D.**
- **Что не так.** В `texts/self/ftwc.md` стоит «не горд��сть» (U+FFFD). Он же есть в сыром ответе `raw/B/ftwc/text0-b8bd5e3a94735a1e62fa.jsonl`. Ни одна проверка его не поймала, и D отвечал по этому тексту.
- **Правка.** В `fabricated()` или в `validate` для A и B браковать ответ с U+FFFD и перезапрашивать.

**7. A дописывает факты, которых нет в записи.**
- **Что не так.** Примеры: «администратор в сетевой стоматологии» (ern9), «держит пост, на Новый год сок» и «телефон куплен в рассрочку» (nihq).
- **Почему это важно.** Это не противоречит записи. Но если досье прочтёт кто-то дальше по конвейеру (оценщики E), он примет выдумку за факт.
- **Правка.** Разрешить бытовые подробности только как иллюстрацию сведений. Отдельно запретить новые факты о деньгах, вере и работе.

**8. Сырые файлы не хранят текст задания, только хеши.**
- **Что не так.** `check_transcripts.py` не может проверить, что во вход роли не попало лишнее. Я восстановил все 105 заданий кодом из `inputs/`, `texts/` и банка: хеши совпали. A получал только «правду», B — только самоотчёт, C — только текст, D — только самоописание и пачку вопросов.
- **Правка.** Сделать такую сверку частью проверки транскриптов или хранить текст задания рядом с сырым файлом.

**9. Уже известные ограничения.**
- Effort виден только в заявке исполнителя. При этом в D есть токены размышлений.
- Все роли — одно семейство, A и D — одна модель (`claude-opus-5-5`). Общего контекста у них нет, но перекосы общие.
- Пятерых недостаточно для сдвига и для проверки 3.3.
