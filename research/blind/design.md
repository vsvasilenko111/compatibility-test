## 0. Зачем и что исправляется

Разбор (`research/metric/journal.md`, запись 2026-10-28; `research/metric/audit.txt`) показал, что нынешняя синтетика
замкнута:

1. Биографии писались парами и под задуманный исход. Автор знал, «хорошая» пара или «плохая».
2. Перекрёстные пары — лёгкие контрасты из разных городов.
3. Ответы на тест и критерий (эксперты, терапевт, симуляция) читали один и тот же текст. Все они — одна модель.
4. Согласие оценщиков между собой (87–96) — это согласие одного взгляда модели с собой, а не верхняя граница точности.

| Было | Стало |
|---|---|
| Автор придумывает человека под пару | Человек — жребий по реальным долям; биография пишется по готовым числам и без знания пары |
| Исход задаёт автор или LLM-оценщик | Исход считает код по заранее записанной формуле (раздел 5); LLM в исходе не участвует |
| Тест и критерий читают один текст | Тест видит только приукрашенное самоописание; исход считается по «правде» |
| Пары — крайние контрасты | Пары собираются после скелетов, внутри города и возраста; дополнительные пары проходят отсев «не доживших» |
| Сходство взглядов «работает» по замыслу автора | Вклад общего сходства взглядов ≈ 0 (раздел 5) |
| Одна точечная формула, видимая владельцу теста | Ансамбль из 30 формул; числа закрыты, открыты семейства, знаки и порядок силы (раздел 5.2) |

**Независимость от теста.** Список переменных взят из задачи и из `research/sources/*`, а не из банка вопросов.
`src/questions/bank.json` и `src/questions/spheres.ts` открывались только для того, чтобы описать роль отвечающего
(153 вопроса, 5 вариантов ответа; около 45 описывают ситуации с партнёром; проценты теста считаются по блокам «дружба»
и «отношения», блок «зрелость» на них не влияет). Код генератора банк не читает. Ни одна переменная, ни один
коэффициент и ни одно правило составления пар не выбирались по вопросам теста. Пересечение тем (дети, деньги, алкоголь)
неизбежно: в модели исхода они стоят потому, что для них в литературе есть эффект.

## 1. Схема конвейера

```
[1] скелеты людей (код, жребий)                         → people.json             — «правда»
[2] слой самоотчёта (код, жребий)                        → selfreport.json         — как человек себя видит и подаёт
[К] калибровка на отдельной популяции 10 000 чел.        → private/model.json      — a_k, τ, α, k, константы, ансамбль
[3] настоящие пары (код, по [1], без [2])                → private/pairs.json
[4] стадия, стаж и U настоящих пар (условно на «дожили»)  → private/pairs.json
[5] разбиение по людям (единица — настоящая пара)        → private/pairs.json
[6] дополнительные пары внутри своей части               → private/pairs.json
[7] их стадия, стаж, U и отсев «не доживших»             → private/pairs.json
[8] исход (код, формула раздела 5)                       → private/outcome*.json, private/leak-threshold.json
[9] досье (LLM-автор A, по [1], по одному человеку)       → dossiers/
[10] самоописание (LLM-автор B, по [2], по одному)        → selfdesc/
[11] проверка текстов (LLM-восстановитель C)              → fidelity/
[12] ответы на тест (LLM-отвечающий D, по [10])           → answers/
[13] сверка ответов с самоотчётом (код, раздел 3.3)       → fidelity/answers.json
[14] оценщики-сравнения (необязательно, LLM E)            → judges/
[15] оценка теста (код): тест против [8]
```

Шаги 1–8, 13 и 15 детерминированы (python3, numpy/scipy, зёрна в разделе 8). Шаги 9–12 и 14 — LLM: фиксируются модель,
семейство, версия, температура и промпт, выход кешируется и хешируется.

Порядок важен: исход [8] считается до того, как появится хоть один текст. Разбиение [5] идёт **до** дополнительных
пар, чтобы те собирались внутри своей части (критик, п. 5).

## 2. Скелет человека

### 2.1. Объём, состав и мощность

- **Первая партия: 100 человек** (50 мужчин, 50 женщин; пол — по построению). Это пилот: на нём проверяется конвейер
  целиком, включая тексты. Решения о тесте на нём принимаются только по крупным эффектам (см. ниже).
- **Города** (квоты — [допущение], поправка 1): Москва 40, Казань 30, Ярославль 30; в каждом пополам мужчины
  и женщины. Казань — ради заметной доли мусульман, Ярославль — средний город. Четыре–шесть городов при 100 людях
  дают пулы по 5–8 человек на пол, в которых ни подбор пар, ни дополнительные сочетания не работают.
- **Возраст**: целые годы 20–30. Базовые веса — 1,1 для 20–24 и 1,0 для 25–30 [допущение]. У мужчин веса наклонены
  к старшим, у женщин к младшим (множитель 1 ± 0,45 по линейке 20…30) — иначе внутри одного возрастного диапазона
  мужчина в паре не может быть старше в среднем (поправка 2). Ожидаемая разница средних — около +1,8 года.

**Мощность (критик, п. 1; посчитано на этой партии, `generation-report.md`, «Мощность»).**
- Главная метрика — ранговая корреляция балла теста с риском распада по скелету (раздел 7). Для «теста, который ловит
  только несовпадения» (формула несовпадений по самоотчёту) она равна 0,16 [−0,22; 0,47] на рабочей части
  (107 пар, 58 человек) и 0,36 [−0,11; 0,71] на проверочной (73 пары, 42 человека). Интервал — 95% бутстрэп по людям.
- AUC по одному жребию на тех же частях: интервалы шириной 0,4–0,5, SD по перетяжкам жребия `V` — 0,06–0,08.
  По нему на 100 людях не решается ничего.
- Разница двух версий теста (парный бутстрэп по людям, главная метрика): SD разницы ≈ 0,08 при небольшой правке,
  то есть минимально различимая разница ≈ 0,2 по Spearman. Разницы в 0,01–0,03 эта партия **не покажет**. Она
  покажет, ловит ли тест индивидуальные риски вообще: добавление к несовпадениям даже 10% индивидуальных рисков
  по самоотчёту меняет Spearman на 0,2–0,3.
- Масштабирование: новые **сочетания** тех же людей не стоят ни одного вызова LLM (балл пары считается из ответов
  двоих), но новых сочетаний внутри части почти нет — при 100 людях использованы почти все правдоподобные (раздел 4.3).
  Узкое место — число людей. Чтобы на проверочной части интервал главной метрики был ±0,1, нужно ≈ 15× больше людей
  в проверочной части (≈ 600). Разумный следующий шаг — 320–400 человек в 4–6 городах (тогда возвращаются
  Санкт-Петербург, Екатеринбург, Тверь); код рассчитан на батчи по 100 человек.

### 2.2. Устройство жребия

Непрерывные черты — многомерное нормальное распределение (гауссова копула) с корреляциями из 2.4. Категории —
пороги на латентных нормалях, пороги ставятся так, чтобы доли совпали с источником. Бинарные события со связью
с чертой тянутся логистически. Пороги и интерсепты подбираются **один раз** на опорной популяции в 200 000 человек
(отдельное зерно) и записываются в `people.json/meta`; на 100 рабочих людях ничего не подгоняется, поэтому их доли
отклоняются от целевых на величину случайности. Человек тянется целиком до составления пар.

3. SD латентных не меньше 0,9 (Bisbee 2024, Wang 2025 [пров.]).

## 3. Модель приукрашивания (социальная желательность)

### 3.1. Черта

`ETA` ~ N(0, 1) — индивидуальная склонность подавать себя лучше. Эмпирического распределения для синтетических
респондентов нет (`methods.md`, 3.3), форма — [допущение], масштаб привязан к источникам ниже.

### 3.2. Как из «правды» получается самоотчёт (исправлено по критику, п. 2)

Для черт с желательным полюсом:

```
x_self = x_true + s_x · d_ix + ε,
d_ix   = max(0, 0,35 + 0,20 · ETA_i + 0,15 · max(0, −s_x · x_true)),   ε ~ N(0, 0,70²)
```

- `s_x` — направление к желательному полюсу: −1 для `N`, `ANX`, `AVO`, `HOST`, `WD`, `SPEND`; +1 для `COMM`, `C`, `A`, `LS`.
- Сдвиг зависит от самой черты: конфликтные, тревожные и транжиры приукрашивают сильнее. Средний сдвиг ≈ 0,4 SD
  (Birkeland 2006: d = 0,44–0,45 у соискателей [ист., непров.]; base-rates, разд. 12: 0,3–0,5 SD).
- `ε` = 0,7 SD — ненадёжность самоотчёта. Получилось r «правда — самоотчёт» = 0,77–0,79 (калибровка; в первой редакции
  было обещано 0,8 при фактических 0,94 — ошибка, критик, п. 2).
- `TRAD`: ±0,15 SD шума без сдвига; оси `VIEWS`: ±0,30 SD шума без сдвига (человек сам формулирует взгляды неточно).

Стигматизированное поведение:

| Поведение | Правило самоотчёта | Ориентир |
|---|---|---|
| `DRINK` | уровень −1 с вероятностью 0,35 + 0,15·d_i (не ниже «не пьёт»); у `RISKY` ещё −1 с вероятностью 0,5; `RISKY` не признаётся никогда | опросы видят 30–60% проданного алкоголя, у сильно пьющих недоучёт больше — Esser 2022 [пров.] |
| `INF_PAST` | признаётся с вероятностью **0,35** | См. ниже |
| `JEAL` | признаётся с вероятностью 0,50 | [допущение] |
| `DEBT_PROB` | признаётся с вероятностью 0,60 (иначе — «обычный кредит») | [допущение] |
| `HOST` «часто» | после сдвига ещё −1 ступень с вероятностью 0,5, если самоотчёт остался «часто» | [допущение] |
| `PARENTS`, `KIDS_WANT`, `KIDS_WHEN`, `CONF`, `REL` (уровень), `age`, `city`, `edu`, `work`, `SMOKE`, роли | без искажения | [допущение] |

**Согласованная логика признания измен (критик, п. 9).** Одна «правда» и две доли признания: в анонимном веб-опросе
ВЦИОМ признаётся 0,75 изменявших (отсюда «правда» = ВЦИОМ / 0,75), в тесте — 0,35. Почему в тесте вдвое реже:
Whisman & Snyder 2007 [пров.] — при присутствии интервьюера признаются в ≈ 5,7 раза реже, чем при анонимном вводе.
Тест заполняется самостоятельно, но его результат увидит партнёр, то есть «наблюдатель» есть, и он заинтересован.
0,35 лежит между 0,75 / 5,7 ≈ 0,13 (полное присутствие наблюдателя) и 0,75 (полная анонимность). Обе доли — [допущение].

### 3.3. Что получается и что меряется отдельно

Два слоя на человека: `people.json` («правда») и `selfreport.json` («как отвечаю»). Модель исхода читает только
первый, тест и всё, что ведёт к нему, — только второй.

Собственная позитивность LLM (Salecha 2024: 1,0–1,2 SD [пров.]) и сжатие разброса сюда не входят и **меряются по
ответам** (исправлено по критику, п. 7). Для вопросов теста, у которых есть прямой аналог в самоотчёте (частота
алкоголя, желаемое число детей, деньги и долги, конфликт, ревность), код сравнивает ответ отвечающего с самоотчётом
того же человека:

- средний сдвиг ответа к желательному полюсу (в SD самоотчёта);
- отношение SD ответов к SD самоотчёта: ниже 0,8 — брак партии (порог `methods.md`, 6.4);
- ранговая корреляция ответа с самоотчётом: ниже 0,5 — брак партии [допущение].

Сопоставление «вопрос ↔ поле самоотчёта» составляется **после** генерации исхода и не может на него повлиять.
Повтор того же персонажа меряет ретест, а не сдвиг модели: сдвиг при каждом повторе одинаков.

## 4. Составление пар

### 4.1. Когда и из кого

Только после того, как готовы все скелеты. Пары составляются по «правде»: люди выбирают друг друга по тому, какие
они есть, с шумом. Только мужчина и женщина, один город, разница возрастов `age_m − age_w` в [−3; +8] (поправка 2).

### 4.2. «Притяжение» и настоящие пары

```
score(m, w) = − Σ_k a_k · |z_k(m) − z_k(w)| − a_isl · [ислам(m) ≠ ислам(w)] − a_age · (age_m − age_w − 2)² + ν_mw,
ν_mw ~ N(0, 1)
```

Веса `a_k` подбираются на калибровочной популяции под цели и замораживаются в `private/model.json`:

| Измерение | Цель r в настоящих парах | Получилось (калибровка) | Источник |
|---|---|---|---|
| религиозность `REL` (латентная) | 0,60 | 0,60 | Alford 2011 вторично [ист., непров.]; для молодых ниже [допущение] |
| образование `EDU` | 0,50 | 0,50 | [допущение]; сверить по RLMS-HSE |
| традиционализм `TRAD` | 0,45 | 0,45 | Luo & Klohnen 2005 [ист., непров.] |
| оси `VIEWS` (среднее) | 0,25 | 0,21 | [допущение] |
| желаемое число детей | 0,30 | 0,30 | [допущение] |
| алкоголь `DRINK` | 0,35 | 0,35 | [допущение] |
| никотин | 0,25 | 0,25 | [допущение] |
| личность (`N`, `ANX`, `AVO`, `HOST`, `A`, `C`, `COMM`) | 0,05–0,10 | 0,00 | в подборе не участвует (поправка 3); Luo & Klohnen: сходство по личности слабое |
| ислам: оба мусульмане среди пар с мусульманином | 85% | 46% | **недостижимо** в пулах по 15–20 человек: в Москве и Ярославле на пул приходится 0–2 мусульманина (поправка 3) |
| возраст м − ж | +2 (SD 2,5) | +1,8 (2,5) | [допущение] |

**Настоящие пары** — максимальное по сумме `score` паросочетание внутри города (`linear_sum_assignment`): 50 пар.
Веса, подобранные под цели, оказываются велики относительно ν (σ = 1): при пулах в 15–20 человек достижимые
корреляции ограничены, и шум ν почти не влияет. Это ограничение малых пулов, а не замысел.

### 4.3. Дополнительные сочетания (исправлено по критику, п. 4–5)

Кандидаты — пары (м, ж) **внутри одной части** разбиения (раздел 7) и одного города, в возрастном окне, кроме
настоящих. Полоса правдоподобия считается по всем допустимым партнёрам **в городе до разбиения**: `score` пары должен
быть не ниже 20-го перцентиля у **каждого** из двоих (поправка 4: отсекаются неправдоподобные; верхнюю границу 80-го
перцентиля сняли — при 100 людях она оставляла 140 кандидатов на 130 нужных пар и убирала самые правдоподобные
сочетания без причины). Жребий без возвращения с весом `exp(score / τ)` (трюк Гумбеля), не больше 5 дополнительных пар
на человека, цель — 130 дополнительных пар (всего 180).

**Отсев «не доживших» (критик, п. 4).** Каждой дополнительной паре тянутся стадия (4.4), стаж и `U`, и по **той же
формуле исхода** считается вероятность прожить назначенный стаж: шаги по 6 месяцев, на каждом риск распада
`1 − (1 − P₃(стаж t))^(6/36)`. Монета против этой вероятности: «не дожившая» пара в выборку не попадает.
Настоящие пары не выбрасываются, но их стаж и `U` перетягиваются, пока пара не «доживёт» (условное распределение
при данном скелете; в среднем 1,4 попытки). В итоге у дополнительных пар доля жёстких несовпадений по детям после
отсева не выше, чем у настоящих (калибровка: 4,9% против 6,2%), а по религиозности выше (18% против 12%) — пары,
составленные без учёта веры, реже совпадают по ней, и отсев это гасит лишь частично.

τ подбирался так, чтобы корреляции по ценностям в дополнительных парах были вдвое ниже, чем в настоящих.
Получилось 0,1–0,5 от настоящих (религиозность 0,28 против 0,60; образование 0,17 против 0,50): при 100 людях
дополнительные пары — это почти **все** правдоподобные сочетания внутри части, и выбор τ мало что меняет.

Тип пары (`real` / `alt`) хранится только в `private/pairs.json`. Исход для обоих типов — одна формула.

Ограничение: каждый человек входит в 1–6 пар (в среднем 3,6), пары зависимы. Бутстрэп — по людям (раздел 7).
Человек при этом состоит в нескольких «отношениях» разных стадий с одним самоописанием: самоописание и досье не
упоминают партнёра, стадию и быт пары, поэтому это не противоречие в текстах, но это **не** реальная популяция пар.
Решения принимаются по настоящим парам либо со взвешиванием (раздел 7).

## 5. Модель исхода

Записана до генерации пар. Ответы на тест не участвуют ни в какой форме. Входы — «правда» из `people.json`, пара
из `private/pairs.json`.

### 5.1. Исход 1: вместе ли через 3 года

```
logit P(распад к 36 мес.) = α_стадия + γ · ln(стаж / 12) + k · ( IND(м) + IND(ж) + MIS(м, ж) + β_sim · SIM(м, ж) ) + U_mw
U_mw ~ N(0, σ_U²) до отсева,  σ_U² = 1,2
распад = 1[ V_mw < P ],  V_mw ~ U(0, 1)
```

- `IND(p)` — индивидуальные риски каждого партнёра (собственный эффект и эффект партнёра приняты равными).
- `MIS` — несовпадения с доказанным эффектом. `SIM` — общее сходство взглядов (стандартизовано на калибровке).
- `U_mw` — специфичное для пары («химия», преданность, признательность). По Joel 2017, 2020 [пров.] сильнейшие
  предикторы, не предсказуемые по людям по отдельности. Тянется жребием и не зависит от скелета **до** отсева
  «не доживших»; после отсева у выживших пар `U` слабо отрицательно связан с риском по скелету (r ≈ −0,11): рискованные
  пары дожили до наблюдения благодаря «химии».
- `γ` — поправка на стаж (критик, п. 8): риск распада падает со стажем (Rosenfeld, HCMST [память]); γ — [допущение],
  отрицательная.
- Остаточная случайность — жребий `V` (логистический шум, дисперсия π²/3).

### 5.2. Факторы: семейства, знаки, порядок силы (исправлено по критику, п. 3)

**Все численные коэффициенты — [допущение].** Из литературы взяты знаки и порядок силы; сами величины — суждение
автора. Подгонка теста под эти числа — подгонка под автора, а не под литературу. Поэтому:

1. точечные числа лежат в `private/outcome-spec.json` (SHA-256 `0d09356f274e785f5fa7d8487b074ed65aaf5ea2f3c85c959ecc26bd94653b56`),
   записаны до генерации пар и исходов и закрыты от владельца теста;
2. у каждого коэффициента априорный интервал: логнормальный множитель, 95% интервал ×/÷2 вокруг точечного, знак
   фиксирован. 30 формул ансамбля вытянуты из этих интервалов (зерно `ensemble`) и лежат в `private/model.json`;
   риск по каждой — в `private/outcome-ensemble.json`. Ранговая согласованность членов ансамбля с точечной формулой
   на калибровке: медиана 0,97, минимум 0,91;

|---|---|---|

| живут вместе без брака | **0,30** (было 0,35) | Andersson 2017 [пров.]: 68% за 15 лет у пар с ребёнком → при постоянном риске ≈ 20% за 3 года; ранние годы рискованнее, у пар без детей риск выше → 0,30 (критик, п. 8: 0,35 опиралось на 15-летнюю цифру напрямую) |
| в браке | 0,15 | ≈ 650 разводов на 1 000 браков, Россия 2022 [пров. по пересказу]; Andersson: 36% за 15 лет (≈ 8,5% за 3 года при постоянном риске), первые годы брака самые рискованные. Тамбовские 1 116 не используются |

`α_стадия` подбирается на настоящих парах калибровочной популяции (10 000 человек, своё зерно) так, чтобы средняя
вероятность распада в стадии совпала с целью **после** условия «дожили до начала наблюдения». Получилось:
0,500 / 0,300 / 0,150, в среднем 0,29.

**Открытый пункт №1 (не закрыт):** HCMST 2017–2020 — доля распавшихся за 3 года среди пар с респондентом 20–30 лет
по стадиям (`datasets.md`, п. 1). Отличие больше 10 п. п. — поправка с оговоркой, что это США.

### 5.4. Доля шума и объяснимая доля разброса (исправлено по критику, п. 8)

**Правило выбора `k`:** формула, применённая к **самоотчёту**, объясняет 0,10 ± 0,02 дисперсии латентного логита
распада внутри стадий. Ориентир — Joel et al. 2020 [пров.]: самоотчёты об индивидуальных различиях объясняют 12%
удовлетворённости в конце наблюдения. Сравнивается то же с тем же: предсказание по самоотчёту, а не по «правде».
`k` ищется на калибровочной популяции, допустимый диапазон [0,5; 1,5].

Калибровка (10 000 человек, 5 000 настоящих пар), доли дисперсии латентного логита внутри стадий:

| | `k = 0,5` | `k = 0,74` | **`k = 0,92` (принято)** | `k = 1,0` |
|---|---|---|---|---|
| скелеты двоих (`IND + MIS + SIM`) | 0,06 | 0,13 | **0,19** | 0,22 |
| — по семействам | | | закрыто (15.1): `private/report-private.json`, `family_shares_calibration` | |
| R² формулы по самоотчёту | 0,03 | 0,07 | **0,10** | 0,11 |
| специфичное для пары `U` | 0,23 | 0,22 | 0,21 | 0,20 |
| шум `V` | 0,71 | 0,67 | 0,63 | 0,61 |
| AUC оракула по скелету (среднее внутри стадий) | 0,60 | 0,65 | **0,69** | 0,70 |
| AUC формулы по самоотчёту | 0,58 | 0,62 | **0,64** | 0,66 |

Ещё при принятом `k`: AUC оракула по скелету и `U` — 0,79. AUC по отдельным семействам закрыты (15.1):
`private/report-private.json`, `family_auc_calibration`. Отчёт по тесту всегда даётся сеткой `k` ∈ {0,5; 0,74; 1,0} (риск по скелету при другом `k` — тот же
порядок пар, меняется только сила связи с выпавшим исходом).

Сравнение с Joel 2020 по `U` (критик, п. 8): «скелеты + `U`» ≈ 0,40 — выше 18%, которые у Joel объясняют **оценки
отношений самим участником** в конце наблюдения. `U` — истинная специфичная для пары часть, а не её самоотчёт;
самоотчёт о ней был бы шумным, поэтому прямого противоречия нет. Но потолок «скелет + `U`» нельзя выдавать за то,
что достижимо по любым ответам.

Около 60% разброса — чистая случайность.

### 5.5. Исход 2: удовлетворённость через 3 года

```
Q    = − √0,12 · z(IND_s + MIS_s + β_sim·SIM) − √0,25 · U_s + √0,63 · e,      e ~ N(0, 1)
U_s  = 0,9 · U / σ_U + √0,19 · U',  U' ~ N(0, 1)
CSI4 = clip( round( 16 + 4,7 · (Q − Q̄) / sd(Q) ), 0, 21 ),   «дистресс» = CSI4 < 13,5
```

`IND_s` — те же семейства с весами под удовлетворённость (`AVO` и `HOST` сильнее, `INF_PAST`, `PDIV` слабее), `MIS_s`
— веса несовпадений ×0,5; числа — в `private/outcome-spec.json`. `z(·)`, `Q̄`, `sd(Q)` — константы калибровки.
Для распавшихся — `null`. В `outcome.json` есть и ожидаемая удовлетворённость (без `e` и `U'`) для всех пар.

### 5.6. Время до распада

`месяц = 1 + floor( 35 · W^{exp(0,5 · z_lp)} )`, `W ~ U(0, 1)`, `z_lp` — стандартизованный полный линейный
предиктор (константы калибровки). Терминальный спад (Bühler & Orth 2025: 0,6–2,3 года [пров.]) не моделируется.

### 5.7. Потолки и порог утечки (исправлено по критику, п. 2)

Считаются кодом (`outcome.py`) до появления первого текста и лежат в `private/leak-threshold.json`:

- **оракул** по скелету — верхний потолок (AUC ≈ 0,69 на калибровке);
- **потолок самоотчёта** — та же формула по `selfreport.json`: AUC ≈ 0,64 на калибровке; на этой партии ранговая
  корреляция с риском по скелету 0,79 по всем парам (рабочая часть 0,76, проверочная 0,77);
- **порог утечки** = потолок самоотчёта + верхняя граница 95% бутстрэпа по людям на своей части. Для проверочной части:
  Spearman 0,90, AUC по одному жребию 0,94 (порог по AUC на 73 парах почти бесполезен — см. 2.1);
- **разумная оценка для теста сходства** — около оракула несовпадений; число закрыто (15.1), оно в
  `private/report-private.json`, `family_auc_calibration`.

Балл теста выше порога утечки — признак утечки, а не успех.

## 7. Разбиение и оценка (исправлено по критику, п. 1, 3, 4)

- **Разбиение по людям.** Единица — настоящая пара; страты город × стадия; проверочная доля 40% (Ярославль — 50%,
  малый пул). Получилось: рабочая часть 58 человек / 107 пар (29 настоящих + 78 дополнительных), проверочная 42 / 73
  (21 + 52). Ни один человек не попадает в обе части. Пар по городам (рабочая / проверочная): Москва 48 / 25,
  Казань 29 / 16, Ярославль 30 / 32.
- **Главная метрика — согласие балла теста с ожидаемым исходом:** ранговая корреляция (Spearman) балла с риском
  распада по скелету (`risk_logit_skeleton`, точечная формула). Она не зависит от жребия `V` (64% разброса) и от `U`.
  Рядом печатается то же для каждой из 30 формул ансамбля (минимум, медиана, максимум).
- **Вспомогательные:** AUC против выпавшего распада с расслоением по стадии; AUC, усреднённый по 1 000 перетяжек `V`
  при данных вероятностях; c-index против месяца распада; ранговая корреляция с CSI-4 у оставшихся вместе.
- **Настоящие и дополнительные пары.** Главная строка — все пары, но с весами, при которых доля несовпадений
  (дети, пьянство, религиозность) равна доле у настоящих пар своей части; рядом — только настоящие и только
  дополнительные.
- **Бутстрэп** — 95% перцентильный, 2 000–4 000 повторов, по людям: тянутся люди части с возвращением, вес пары —
  произведение кратностей двоих.
- **Правило решений.** Правка теста принимается, только если на рабочей части нижняя граница парного бутстрэпа
  разницы главной метрики > 0 **и** правка выигрывает у большинства (≥ 20 из 30) формул ансамбля. **Заменено:**
  действующее правило — 13.3 (плюс выигрыш в каждом варианте другого устройства, сейчас их 16, 15.3).
  Проверочная часть — **не больше 3 запусков на партию** (13.5); скрипт оценки слепой выборки получает пары и исходы
  проверочной части только через `seal.py --open "<решение>"`, который сначала регистрирует запуск и отказывает
  после третьего (15.4). `research/scripts/metric/audit.ts --holdout` относится к прежней синтетике и к этой
  выборке не подключён.
- **Мощность** — раздел 2.1: на этой партии различимы только крупные изменения (≈ 0,2 по Spearman).
- **Шум генерации ответов** — разброс балла при ретесте 10% людей.

### 8.2. Печать исходов

Всё закрытое лежит в `private/`: `outcome-spec.json`, `model.json`, `pairs.json`, `outcome.json`,

### 8.3. Риск «учить под модель» (исправлено по критику, п. 3)

Числа формулы — суждение автора. Подгонка теста под них — подгонка под автора. Защита:

- владелец теста не видит ни скелетов, ни текстов, ни точечных коэффициентов, ни ансамбля, ни риска по скелету;
  у него — ответы, исходы рабочей части и агрегатная сводка. Семейства переменных и знаки (5.2) он видит, и это
  осознанно: тест о совместимости вправе спрашивать про детей и алкоголь, если это оправдано литературой, а не
  этой выборкой;
- правка должна выигрывать у большинства формул ансамбля, а не у одной точечной;
- **оговорка:** первая редакция этого документа содержала точечные числа. Кто её читал, знает центральную формулу.
  Ансамбль и закрытые скелеты снижают пользу от этого знания, но не обнуляют её; это записано как ограничение;
- любое изменение теста фиксируется в журнале до запуска на проверочной части; проверочная часть — не больше 3
  запусков на партию (13.5, 15.4);
- внешняя проверка на живых парах (30–50 пар, CSI-4 сейчас и через 6–12 месяцев; `methods.md`, 6.6) остаётся
  единственным способом проверить саму формулу.

### 13.3. Ансамбль другого устройства формулы и правило приёма правки

Отдельные файлы `ensemble_structural.py`, `private/outcome-ensemble-structural-spec.json` (правила записаны до просмотра
результата) и `private/outcome-ensemble-structural.json` (риск каждого варианта на каждой паре). `model.json`
и цепочка хешей не тронуты. Выпавший исход по-прежнему считается по точечной формуле. 13 вариантов (с редакции 4 — 16, см. 15.3):

1. вес несовпадений ×2, ×3, ×4 при индивидуальных рисках ×0,5 (3 варианта);
2. эффект партнёра 0,5 от собственного: пару разрушает тот, кому хуже, — max(свой + 0,5·партнёра) по двоим;
3. выпадение по одному семейству: индивидуальные риски целиком; только непрерывные; только бинарные; несовпадения;
   сходство взглядов (5 вариантов);
4. взаимодействия: оба тревожные; тревожный + избегающий (требование — уход); максимум враждебности двоих вместо суммы;
   все три вместе (4 варианта).

**Правило приёма правки теста (заменяет правило раздела 7).** Правка принимается, только если на рабочей части
нижняя граница парного бутстрэпа разницы главной метрики > 0, правка выигрывает у ≥ 20 из 30 формул прежнего ансамбля
**и выигрывает в каждом варианте устройства** (13, с редакции 4 — 16; 15.3). Если правка проигрывает хоть в одном варианте, вопрос
«индивидуальное против парного» на этой партии не решён, и правка не принимается.

**Ограничение.** Раздел 5.4 этого документа (до редакции 4) и прежняя редакция `generation-report.md` показывали
соотношение вкладов семейств; с редакции 4 эти числа убраны и из design.md (15.1). Кто это читал, знает его. Новый ансамбль снижает пользу этого знания: правка, которая опирается только
на одно семейство, проигрывает в варианте с его выпадением. С этой редакции доли и AUC по семействам в
`generation-report.md` не печатаются (они в `private/report-private.json`).

### 13.4. Флаг выборки и сбалансированный жребий

- `report.py` сравнивает ключевые доли и средние выборки с ожиданием генератора (калибровочная популяция) и печатает
  z = отклонение / SE. |z| > 2 — строка «Выборка вне ±2 SE» в разделе «Не сошлось». Дополнительно — знаковый тест:
  сколько отклонений направлено в «здоровую» сторону. При p < 0,05 — строка «выборка сдвинута в одну сторону».
- **Для следующих партий объявлено заранее:** жребий внутри батча — сбалансированный (систематическая выборка или
  латинский гиперкуб) по ключевым бинарным признакам (не пьёт, надёжная привязанность, измены в прошлом, развод
  родителей) и доле ислама по городам. Схема балансировки записывается до запуска. **Подбор зерна по результату
  запрещён.** Эта партия остаётся как есть: её отклонения напечатаны в отчёте.

### 13.5. Граница применимости и лимит проверочной части

- **Вопросы о ситуациях конкретной пары эта партия не проверяет.** Досье и самоописание не упоминают партнёра, стадию
  и быт, а отвечающий отвечает на вопросы о ситуациях с партнёром гипотетически. Специфика пары (`U`, доля быта)
  в тексты не попадает. Поэтому решения по блокам теста, которые спрашивают о текущих отношениях, на этой партии

  на каждую пару — возможное расширение (≈ 180 прогонов ответов, человек в нескольких «отношениях» с разными ответами).
- **Лимит запусков проверочной части — не больше 3 на партию.** Каждый запуск регистрируется

### 15.3. Сильные взаимодействия в ансамбле другого устройства (критик 3, п. 3)

Дописаны 3 варианта (в `private/outcome-ensemble-structural-spec.json`, ключ `_note_v2`; **после** просмотра согласия
вариантов 10–13 — записано в спеке). Вес каждого взаимодействия подбирается на настоящих парах калибровочной
популяции так, чтобы SD его вклада была сопоставима с SD индивидуальных рисков пары; индивидуальные риски и
несовпадения не ослабляются:

14. тревожный + избегающий (бинарный индикатор), сила как у индивидуальных рисков;
15. требование — уход, непрерывная форма: `ANX_м·AVO_ж + ANX_ж·AVO_м`;
16. то же плюс «оба тревожные» `ANX_м·ANX_ж`.

Бинарная форма на этой партии покрывает мало пар, поэтому почти не меняет ранжирование; непрерывные формы ранжируют
пары заметно иначе (согласие — в `private/outcome-ensemble-structural.json`, поле `agreement`). Правило 13.3 теперь —
выигрыш в каждом из 16 вариантов, то есть гипотезу «требование — уход» ансамбль проверяет.

### 15.4. Лимит проверочной части держится кодом, а не только протоколом (критик 3, п. 4)

- `seal.py --open "<решение>"` — **единственный** разрешённый путь, которым скрипт оценки получает пары и исходы
  проверочной части: сверяет печать, регистрирует запуск и только потом печатает данные в stdout. После третьего
  запуска — отказ.
- Каждый запуск записывается в два места: `private/holdout-runs.jsonl` и файл `sealed/runs/run-<n>.json` (444).
  Счётчик — максимум из двух, поэтому удаление jsonl лимит не сбрасывает; `seal.py --verify` падает, если журналы
  расходятся.
- `seal.py --rehash "<причина>"` перепечатывает в `sealed/MANIFEST.json` только ссылки на хеши `private/pairs.json`
  и `outcome.json`, если сами пары и исходы проверочной части побайтно те же; каждая перепечатка — файл
  `sealed/rehash/rehash-<n>.json` (444). Понадобилось один раз в этой редакции: новые поля изменили `people.json`,
  а через него хеши в `pairs.json` и `outcome.json`.
- Раздел 7 и 8.2–8.3 теперь ссылаются на 13.3, 13.5 и этот пункт.
- **Не согласен частично:** критик предлагал, чтобы `research/scripts/metric/audit.ts --holdout` вызывал
  `seal.py --register`. `audit.ts` проверяет банк вопросов на прежней синтетике со своим разбиением и своим логом;
  если подключить его к счётчику слепой выборки, каждый синтетический аудит сжигал бы один из трёх запусков этой
  партии. Скрипта оценки на слепой выборке ещё нет; когда он появится, он будет читать проверочную часть только
  через `seal.py --open`. Права файлов от агента того же пользователя не защищают (13.1, п. 6), так что последняя
  опора — по-прежнему журнал и аудит.

### 15.5. Проверка транскриптов (критик 3, п. 5)

`check_transcripts.py` теперь принимает только **сырой JSON API** (`.json` или `.jsonl`); пересказ без

чтение файла (`cat`, `ls`, `grep`, `open(`, `*.json` и т. п.). Протокол 13.1: транскрипты хранятся сырыми.

### 16.1. Вызов роли (замечание критика до пилота, п. а)

Каждый вызов — отдельный процесс из свежего пустого каталога `mktemp -d` вне проекта:

```
claude -p "<задание>" --model <полное имя> --effort <из models.json> --tools "" --strict-mcp-config
  --mcp-config '{"mcpServers":{}}' --setting-sources project --no-session-persistence
  --system-prompt "<своё для роли>" --output-format stream-json --verbose
```

- **`--bare` не используется.** Проверено 2026-10-28 (Claude Code 2.1.311): с `--bare` вызов падает с «Not logged in»
  (`--bare` принимает только `ANTHROPIC_API_KEY`, вход по OAuth не читается, а ключа в окружении нет). Его задачу —
  не подмешивать CLAUDE.md, память, хуки и MCP пользователя — закрывают: `--setting-sources project` из пустого
  каталога (настройки и хуки пользователя не читаются), `--strict-mcp-config` с пустым `--mcp-config`, `--tools ""`,
  свой `--system-prompt` (заменяет системный промпт по умолчанию вместе с CLAUDE.md и памятью). Пробный вызов:
  в кеш записано ≈ 600 токенов системной части — CLAUDE.md пользователя туда не попал.
- Из окружения процесса убираются переменные `CLAUDE_CODE_*`, `CLAUDECODE`, `CLAUDE_EFFORT` вызывающей сессии.
- Первой строкой сырого файла пишется заявка исполнителя (`type: "runner_request"`: роль, заказанные модель и effort,
  хеши промптов), дальше — поток `stream-json` как есть.

### 16.5. Восстановитель C: анкета из 12 полей

Тревожность в отношениях, избегание близости, эмоциональная неустойчивость (по 5 уровней); критика и враждебность

сдвиг D к желательному против самоотчёта **+0,28 ступени** в среднем по сопоставлению 16.8 (95% интервал 0,12–0,44),
неравномерно: уход от разговора +0,58 SD, тревожность (`trauma-06`) +0,46 SD, критика (`conflicts-02`) +0,42 SD,
алкоголь и дети 0. Это собственная положительность D, а не новая ошибка (критик 04, п. 3).

Решения по обязательным пунктам критика 04:

1. **Сферы вне записи.** Синтетика **не судит** о правках вопросов в сферах, которых нет в записи человека: досуг,
   общение и внимание, проявления любви, питание, спорт. Юмор, близость и родня с этой редакции получают поля (раздел 17),
   но тексты пилота написаны без них; до прогона на 100 с новыми текстами о правках этих трёх сфер синтетика тоже не судит.
   На синтетике **не подбираются** множитель важных сфер и их список: выбор сфер D делает по устройству текста, а не по
   человеку (критик 04, п. 1). Главная метрика печатается **дважды** — с выбранными 5 важными сферами и без них (все
   сферы ×1). Если выводы расходятся, верить варианту без важных сфер.
2. **Сопоставление 3.3 и скрипт проверки порции** — 17.11 (пороги, записаны до прогона) и 17.12 (сопоставление,
   составлено после генерации исхода ред. 5, как требует 3.3); `conflicts-02` заменён на `regul-07` и `regul-01`.
3. **Правило остановки по сдвигу D** — 17.11.
4. **Порядок запуска.** Порциями по 15–20 человек через `--ids`, перед каждой порцией — загрузка окна; после каждой
   порции — `batch_check.py` (17.11). Перед расчётом метрики — проверка, что у всех людей тексты и ответы сделаны
   одними и теми же заданиями (`batch_check.py`, проверка версий; старые сырые файлы jmsb и первые четверо пилота
   переписываются — у них другая запись и другие задания).

Ограничения, которые остаются (желательные пункты критика 04 не делались): B проходит почти по всем полям записи
и повторяет обороты, манеры B не связаны со склонностью приукрашивать; синтетика завышает силу вопросов, у которых
есть прямое поле в записи, по сравнению с остальными (критик 04, п. 5); C не проверяет «глава семьи», «тайно проверял
телефон» и «привирает».

Ни один новый фактор не сильнее «сильных» ред. 4 (`COMM`, `HOST`, `RISKY`, `INF`) и несовпадения по детям.

Формула распада ред. 5:

```
logit P(распад к 36 мес.) = α5_стадия + γ · ln(стаж / 12) + k5 · ( IND + MIS + β_sim·SIM + IND5 + PAIR5 ) + U5
IND5  = собственный агрессивный юмор двоих;   PAIR5 = свойства пары (17.3) с весами ред. 5
U5    = (σ_U5 / σ_U) · U   (U — из pairs.json, ранжирование «химии» то же)
```

- `σ_U5` подбирается так, чтобы **вся** специфичная для пары дисперсия — `U5` плюс та часть `k5·PAIR5`, которая не
  выводится из двоих людей, — равнялась прежней `σ_U²` = 1,2 (внутри стадий, настоящие пары калибровки). Основание:
  общий юмор пары — часть `U` (Hall 2017), удовлетворённость сексом — во многом состояние пары (БР 16.2), поэтому
  новые свойства пары «вырезают» свою долю из `U`, а не добавляют новую.
- **Риск по скелету (главная метрика, раздел 7)** ред. 5 = `k5 · (IND + MIS + β·SIM + IND5 + E[PAIR5 | двое])`.
  Ожидание — среднее по 256 перетяжкам стадии (4.4), стажа, `U` и шумов образования свойств при данных двух людях
  (зерно `expect_r5`). Специфичная для пары часть свойств, как и `U`, в главную метрику не входит. Реализованный
  линейный предиктор с фактическими свойствами пары лежит рядом (`private/outcome.json`, закрыто).
- Удовлетворённость (5.5): та же форма; в `IND_s` добавлены члены ред. 5, свойства пары — реализованные. Доля
  «скелет вместе со свойствами пары» увеличена, доля `U_s` уменьшена так, что их сумма та же (0,37); числа — в спеке.
- Время до распада (5.6) — по линейному предиктору ред. 5.

### 17.6. Калибровка ред. 5 (`calibrate_r5.py` → `private/model-r5.json`; правила записаны до запуска)

- Калибровочная популяция, настоящие и дополнительные пары, их стадии, стаж и `U` — те же, что в `calibrate.py`
  (воспроизводятся по тем же потокам; код сверяет с `model.json`, что предыстория совпала).
- `α5`: средняя вероятность распада по стадиям на настоящих парах калибровки = 0,50 / 0,30 / 0,15 (5.3).
- `k5`: правило 5.4 — R² формулы ред. 5, применённой к самоотчёту (свойства пары — их ожидание по самоотчёту двоих), =
  0,10 ± 0,02, `k5` ∈ [0,5; 1,5]; при выходе за диапазон — граница и пометка в отчёте. `σ_U5` пересчитывается при
  каждом `k`.
- Потолки (5.7) — оракул по скелету, потолок самоотчёта, порог утечки — `outcome.py` по ред. 5, до первого текста.
- **Проверка «в пределах ориентира Joel 2020»** (печатается в `generation-report.md`, «Объяснимая доля», без
  разбивки на семейства): R² по самоотчёту 0,08–0,12; «скелет + вся специфичная для пары часть» ≤ 0,45 (ред. 4:
  ≈ 0,40); шум `V` ≈ 0,6; AUC оракула по скелету — рядом с ред. 4. Нарушение — строка в «Не сошлось».

### 17.11. Проверка порции и правило остановки по сдвигу D (критик 04, обязательные п. 2 и 3; записано до прогона)

Скрипт `batch_check.py --ids <id…>` (читает `inputs/`, `texts/`, `answers/`, `raw/`, банк; `private/` и `sealed/` не
читает) по сопоставлению 17.12 считает для каждого вопроса и каждой сферы: отношение SD ответов D к SD самоотчёта,
ранговую корреляцию ответа с самоотчётом, сдвиг ответа к желательному полюсу против самоотчёта (в SD самоотчёта)
и то же против «правды» справочно. Уровни записи переводятся в шкалу 1..5 линейно, как в 16.8.

**Вердикт «брак порции»**, если выполнено хоть одно:
1. медиана отношения SD по вопросам сопоставления < 0,8 или медиана ранговой корреляции < 0,5 (порог 3.3);
2. у отдельного вопроса отношение SD < 0,6 или ранговая корреляция < 0,3 (грубый сбой; пороги ниже 3.3 из-за шума
   при n = 15–20 — [допущение]);
3. проверка версий: у кого-то из порции задания A, B, C или D (системный промпт и шаблон задания в заголовке `raw/`)
   не те, что в действующем `prompts/roles.json`;
4. у D не 153 ответа, пропуск у обязательного, отметка «не обсуждается» не у `firm`, не 5 сфер.

**Правило остановки по сдвигу** (измерено во втором пилоте: +0,28 ступени в среднем, до 0,58 SD по вопросу):
**остановка и разбор**, если средний сдвиг D к желательному против самоотчёта по направленным вопросам сопоставления
**> 0,4 SD** или по любой сфере (среднее по её вопросам) **> 0,6 SD**. Считается по порции и нарастающим итогом.
Вопросы без направления (дети) в сдвиг не входят. Подбор порции, вопросов или порогов по результату запрещён.
