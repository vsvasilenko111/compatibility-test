# Тест совместимости «Отношения и дружба» — дизайн

Дата: 2026-10-15
Статус: черновик на ревью

## 1. Цель

Личный проект: объёмный тест, который каждый проходит сам. Сравнив результаты двух людей,
тест показывает их совместимость **в отношениях** и **в дружбе**. Тестом делятся ссылкой.

Критерии успеха:
- двое проходят тест на своих телефонах независимо и получают результат, не регистрируясь и без сервера;
- результат — не только процент, а разбивка по сферам, красные флаги, сильные совпадения и темы для разговора;
- конкретные ответы партнёра не раскрываются;
- формулировки вопросов не подсказывают «правильный» ответ.

Вне рамок v1: отдельный тест «Друзья» (заложен в архитектуру, не реализуется), личный профиль
после одиночного прохождения, Telegram Mini App, сервер и аккаунты.

## 2. Пользовательский сценарий

1. Аня открывает сайт → вступление (≈45 минут, «ваши ответы партнёр не увидит», имя — по желанию).
2. Проходит ≈116 вопросов. Прогресс автоматически сохраняется в браузере.
3. Финал: ссылка `…/#a=<код Ани>` + кнопки «Поделиться» (Web Share API) и «Скопировать».
4. Миша открывает ссылку → «Аня приглашает вас проверить совместимость» → проходит тот же тест.
5. Миша сразу видит результат и кнопку «Отправить результат Ане». Ссылка `…/#a=<код Ани>&b=<код Миши>`
   открывает тот же результат у кого угодно без прохождения.

## 3. Архитектура

Статический сайт (Vite + TypeScript, без UI-фреймворка), хостинг на GitHub Pages. Сервера нет.

| Модуль | Ответственность | Зависимости |
|---|---|---|
| `questions` | Банк вопросов (JSON) + манифест версий банка | — |
| `codec` | Ответы ⇄ короткая запутанная строка с версией и контрольной суммой | `questions` (манифест) |
| `scoring` | Чистая функция: ответы двух людей → проценты, сферы, флаги, награды | `questions` |
| `storage` | Сохранение и восстановление прогресса в `localStorage`, с запасным режимом без него | — |
| `ui` | Экраны и маршрутизация по `location.hash` | все выше |

`scoring` и `codec` не знают об интерфейсе и тестируются изолированно.

## 4. Формат вопроса

Каждый вопрос — шкала 0–10 между двумя полюсами.

```json
{
  "id": "money-07",
  "block": "friendship",
  "sphere": "money",
  "text": "Вам неожиданно пришли 50 000 ₽",
  "left": "Отложу всё до копейки",
  "right": "Потрачу на впечатления",
  "topic": "отношение к неожиданным деньгам",
  "optional": false
}
```

- `id` неизменяем после публикации; текст можно править.
- `block`: `friendship` | `relationship`.
- `topic` — нейтральная фраза для экрана результата, ответов не раскрывает.
- `optional: true` — деликатный вопрос с кнопкой «Пропустить».

На каждый вопрос человек даёт три ответа:
1. **Мой ответ** — точка 0–10.
2. **Приемлемо для партнёра** — диапазон `[lo, hi]` на той же шкале; по умолчанию `±2` от моего ответа, обрезанный до 0..10.
3. **Важность** — 4 уровня: не важно / немного / очень / критично (веса 0 / 1 / 10 / 50).
   Не больше **12 «критично»** на весь тест, на экране счётчик.

## 5. Банк вопросов

### Блок «Дружба» (≈60 вопросов, 8 сфер × 7–8), формулировки нейтральные («близкий человек»)

1. Юмор и вайб
2. Досуг
3. Ритм общения
4. Лояльность и поддержка
5. Честность и границы
6. Деньги между людьми
7. Ценности и мировоззрение
8. Конфликты

### Блок «Отношения» (≈56 вопросов, 9 сфер × 6–7)

1. Дети и семья
2. Быт и дом
3. Где и как жить
4. Карьера и амбиции
5. Семейный бюджет
6. Близость (вопросы `optional`)
7. Ревность и личное пространство
8. Родственники и окружение
9. Роли и языки любви

### Правила составления

- Приёмы против очевидных ответов: ситуации, выбор между двумя одинаково привлекательными вариантами,
  компромиссы с ценой, вопросы о прошлом поведении (деньги, привычки). Оба полюса звучат приемлемо.
- «Социально одобряемый» полюс то слева, то справа.
- Бинарные темы (хотите ли детей) — тоже шкала: 0 = точно нет, 5 = не уверен, 10 = точно да.
- Порядок вопросов перемешан один раз заранее, одинаков у всех; два вопроса одной сферы подряд не идут; названия сфер при прохождении не показываются.

Черновик всех вопросов пишет Claude отдельным этапом, пользователь вычитывает.

## 6. Алгоритм

Обозначения на один вопрос: `a`, `b` — ответы Ани и Миши; `[loA, hiA]` — диапазон Ани; `wA ∈ {0,1,10,50}`.
Вопрос, пропущенный хотя бы одним, исключается из подсчёта для обоих.

### 6.1 Попадание в диапазон

```
d    = max(0, loA − b, b − hiA)
fitA = max(0, 1 − d / 3)          // внутри = 1; 1 деление = 0,67; 2 = 0,33; ≥3 = 0
```
`fitB` — симметрично.

### 6.2 Процент совместимости

```
S_A  = Σ(wA · fitA) / Σ wA
S_B  = Σ(wB · fitB) / Σ wB
Итог = √(S_A · S_B) · 100%
```

- Если `Σ wA = 0` (Ане ничего в этом наборе не важно), `S_A = 1`.
- Если у обоих `Σ w = 0` — вместо процента «Для вас обоих не принципиально».
- **Отношения** — по всем вопросам теста. **Дружба** — только по вопросам блока `friendship`.
- По сферам — та же формула на вопросах сферы.

### 6.3 Сила совпадения (только для наград, на процент не влияет)

```
если (a − 5)·(b − 5) > 0:                 // строго по одну сторону от центра
    k            = (|a − 5| + |b − 5|) / 2
    убеждённость = 1 − (1 − k/5)²
    близость     = max(0, 1 − |a − b| / 4)
    сила         = убеждённость · близость · min(fitA, fitB)
иначе:
    сила = 0
```

Эталонные значения (при `fit = 1`): 10/10 → 1,00; 9/9 → 0,96; 8/8 → 0,84; 10/9 → 0,74; 9/8 → 0,68;
7/7 → 0,64; 8/7 → 0,56; 10/8 → 0,48; 9/7 → 0,42; 6/6 → 0,36; 5/5 → 0; 2/8 → 0.

### 6.4 Блоки результата (отдельно для «Отношений» и «Дружбы»)

| Блок | Условие | Сортировка | Показ |
|---|---|---|---|
| 🔴 Красный флаг | у кого-то `w = 50` и `fit = 0` | по сумме весов | все |
| 🌟 Супер-совпадение | `сила ≥ 0,8`, у обоих `w ≥ 10` | `сила · (wA + wB)` | топ-5 |
| 🟢 Сильное совпадение | `0,5 ≤ сила < 0,8`, у обоих `w ≥ 10` | `сила · (wA + wB)` | топ-5 |
| 🟠 Зона для разговора | у кого-то `w ≥ 10` и `fit < 1`, не красный флаг | `wA·(1−fitA) + wB·(1−fitB)` | топ-5 |
| ⚪ Оба гибкие | — | — | только счётчик |

Каждый пункт показывается через `topic` вопроса. Плюс счётчик «N супер-совпадений».

## 7. Кодирование ссылки (`codec`)

- На вопрос 14 бит: ответ (4), `lo` (4), `hi` (4), важность (2). Значение ответа `15` — «пропущен».
- Заголовок: версия формата (1 байт), версия банка (1 байт), тип теста (1 байт, в v1 всегда «отношения»;
  поле под будущий тест «Друзья»), имя (UTF-8 с префиксом длины, ≤ 40 байт — обрезается по границе символа).
- Хвост: CRC-16 по всему содержимому.
- Запутывание: XOR с фиксированной псевдослучайной гаммой → base64url. Это не защита, а только
  скрытие очевидного содержимого. Это осознанно принимаем.
- Длина одного кода ≈ 310 символов; ссылка с результатом (`#a=…&b=…`) ≈ 630.
- Манифест `bank-versions.json` хранит упорядоченный список `id` для каждой версии банка. Декодер
  восстанавливает ответы по `id`; сравниваются только вопросы, которые есть у обоих.

## 8. Экраны

1. **Вступление** — описание, имя, «Продолжить с вопроса N», если есть сохранённый прогресс.
2. **Вопрос** (сначала для телефона) — текст; шкала «Мой ответ»; двухползунковый диапазон «Приемлемо для партнёра»;
   4 кнопки важности + «Критично: 7 из 12»; прогресс «47 / 116»; «Назад»; «Пропустить» у `optional`.
3. **Финал** — ссылка, «Поделиться», «Скопировать».
4. **Приглашение** (`#a=`) — «<Имя> приглашает вас…» → тест.
5. **Результат** (`#a=&b=`) — 💞 Отношения X% и 👯 Дружба Y%; короткий итоговый вывод; разбивка по сферам;
   блоки 🔴 → 🌟 → 🟢 → 🟠 для каждого режима; «Отправить результат партнёру».

## 9. Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Повреждённая или обрезанная ссылка (CRC не сходится) | «Ссылка повреждена, попросите прислать заново» |
| Неизвестная версия формата | «Ссылка от более новой версии теста — обновите страницу» |
| Банк вопросов изменился | Сравнение по пересечению `id`; неизвестные `id` пропускаются |
| Человек открыл свою же ссылку (код совпадает с сохранённым) | «Это ваша ссылка — отправьте её партнёру» |
| `localStorage` недоступен | Тест работает, предупреждение «прогресс не сохранится» |
| Лимит «критично» исчерпан | Кнопка неактивна, подсказка «снимите критично с другого вопроса» |

## 10. Тестирование (Vitest)

- `scoring`: все эталонные значения из 6.3; пример Ани и Миши; односторонняя совместимость;
  `Σw = 0`; пропущенные вопросы; 0/10 → сила 0; отдельный подсчёт «Дружбы» по блоку.
- `codec`: прямой и обратный проход на случайных ответах; повреждение любого символа ловится CRC;
  длина кода ≤ 340; имя с кириллицей и эмодзи; декодирование старой версии банка по манифесту.
- Банк: уникальность `id`, у каждого вопроса есть все поля, объём сфер в пределах плана,
  нет двух вопросов одной сферы подряд.
- Вручную: полное прохождение вдвоём на двух телефонах через Telegram.

## 11. Этапы

1. Движок: `scoring`, `codec`, `storage` + тесты, на заглушечном банке из 10 вопросов.
2. Интерфейс: все экраны, адаптивная вёрстка, сначала для телефона.
3. Банк вопросов: черновик ≈116 вопросов → вычитка пользователем.
4. Публикация на GitHub Pages, ручная проверка вдвоём.
5. (Позже) Отдельный тест «Друзья» = только блок `friendship` + выбор теста на старте.
